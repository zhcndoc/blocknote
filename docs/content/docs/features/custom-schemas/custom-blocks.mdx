# 自定义区块类型

除了 BlockNote 提供的默认区块类型外，您还可以使用 React 组件自行创建自定义区块。请看下面的演示示例，我们在 BlockNote 编辑器中添加了一个自定义警告区块，同时添加了一个自定义的 [斜杠菜单项](/docs/react/components/suggestion-menus#changing-slash-menu-items) 用于插入该区块。

## 创建自定义区块类型

使用 `createReactBlockSpec` 函数来创建自定义区块类型。该函数接受三个参数：

```typescript
function createReactBlockSpec(
  blockConfig: CustomBlockConfig,
  blockImplementation: ReactCustomBlockImplementation,
  extensions?: BlockNoteExtension[],
): (options? BlockOptions) => BlockSpec;
```

它返回一个函数，您可以调用该函数来创建自定义区块的实例，或者创建一个 `BlockSpec`。该 `BlockSpec` 随后会传入您的 [BlockNote schema](/docs/features/custom-schemas#creating-your-own-schema)，以将区块添加到编辑器中。此函数也可以接受任意选项，您可以在[下方](/docs/features/custom-schemas/custom-blocks#block-config-options)了解更多相关内容。

让我们来看演示中的自定义警告区块，并逐一说明各字段的作用：

```typescript
const createAlert = createReactBlockSpec(
  {
    type: "alert",
    propSchema: {
      textAlignment: defaultProps.textAlignment,
      textColor: defaultProps.textColor,
      type: {
        default: "warning",
        values: ["warning", "error", "info", "success"],
      },
    },
    content: "inline",
  },
  {
    render: (props) => {
      ...
    },
  }
);
```

### 区块配置 (`CustomBlockConfig`)

区块配置描述了自定义区块的结构。用它来指定区块的类型、属性（props）以及内容支持：

```typescript
type BlockConfig = {
  type: string;
  content: "inline" | "plain" | "none";
  readonly propSchema: PropSchema;
  layoutOnly?: boolean;
  children?:
    | { allow?: "blocks"; exclude?: string[] }
    | { allow: string[]; min?: number; dissolve?: boolean };
  placeable?: "anywhere" | "namedOnly";
};
```

`type:` 定义自定义区块的标识符。

`content:` 定义区块包含哪种可编辑内容：

- `"inline"` 用于富文本内容，即[内联内容](/docs/foundations/document-structure#inline-content-objects)，例如带样式的文本和链接。
- `"plain"` 用于无样式的纯文本，例如代码区块的源代码。纯文本内容不能包含格式标记（粗体、斜体等）或其他内联内容，并且它是唯一支持[语法高亮](/docs/features/blocks/code-blocks#syntax-highlighting)的内容类型。
- `"none"` 表示区块不包含可编辑内容。

<Callout type="info">
  _在警告演示中，我们希望用户能够在警告区块中输入富文本，因此将 `content` 设置为 `"inline"`。_
</Callout>

<Callout type="info">
  _每个区块都可以包含缩进显示在其下方的子区块，无需在配置中声明。要为区块内容及其子区块绘制框架，请参阅[区块框架](#block-frames)。`layoutOnly`、`children` 和 `placeable` 仅用于布局块。布局块只容纳并排列其他区块，自身没有内容，例如面板或标签页组。请参阅[布局块](/docs/features/custom-schemas/layout-blocks)。_
</Callout>

`propSchema:` `PropSchema` 指定区块支持的属性。区块属性（props）是存储在文档中的数据，可用于自定义其外观或行为。

```typescript
type PropSchema<PrimitiveType extends "boolean" | "number" | "string"> = Record<
  string,
  | {
      default: PrimitiveType;
      values?: PrimitiveType[];
    }
  | {
      default: undefined;
      type: PrimitiveType;
      values?: PrimitiveType[];
    }
>;
```

`[key: string]` 是属性的名称。如果您希望它有默认值，应定义为包含以下属性的对象：

- `default:` 指定属性的默认值，由此推断出 `PrimitiveType`。

- `values?:` 指定属性可取的值数组，例如用于限制值为预定义字符串列表。如果未定义 `values`，BlockNote 会假设该属性可以为任意 `PrimitiveType` 的值。

如果您不希望该属性有默认值，可以定义为包含以下属性的对象：

- `default:` 置为 `undefined`，表示无默认值。

- `type:` 指定该属性允许的 `PrimitiveType`，因为默认值为 `undefined` 无法推断类型。

- `values?:` 指定该属性可取的值数组，用于限制为预定义字符串列表。如果未定义 `values`，BlockNote 会假设该属性可以为任意 `PrimitiveType` 的值。

<Callout type="info">
  _在警告示例中，我们添加了名为 `type` 的属性，用于指定警告类型（警告 / 错误 / 信息 / 成功），还添加了从[默认区块属性](/docs/features/blocks#default-block-properties)继承的文本对齐和文本颜色属性，以支持基本样式选项。_
</Callout>

### 区块实现 (`ReactCustomBlockImplementation`)

区块实现定义了区块在编辑器中的渲染方式，以及如何从 HTML 解析和转换为 HTML。

```typescript
type ReactCustomBlockImplementation = {
  render: React.FC<{
    block: Block;
    editor: BlockNoteEditor;
    contentRef?: (node: HTMLElement | null) => void;
  }>;
  renderFrame?: React.FC<{
    block: Block;
    editor: BlockNoteEditor;
    slotRef: (node: HTMLElement | null) => void;
  }>;
  toExternalHTML?: React.FC<{
    block: Block;
    editor: BlockNoteEditor;
    contentRef?: (node: HTMLElement | null) => void;
    childrenRef: (node: HTMLElement | null) => void;
    context: { nestingLevel: number };
  }>;
  parse?: (element: HTMLElement) => PartialBlock["props"] | undefined;
  parseContent?: (options: {
    el: HTMLElement;
    schema: Schema;
  }) => Fragment | undefined;
  runsBefore?: string[];
  experimental_keyboard?:
    | KeyboardSettings
    | ((block: Block) => KeyboardSettings);
  // KeyboardSettings: {
  //   enter?: "split" | "into-children" | "line-break";
  //   shiftEnter?: "line-break" | "same-as-enter";
  //   splitKeepsType?: boolean;
  //   splitKeepsChildren?: boolean;
  //   resetsTo?: { type: string; props?: Record<string, unknown> };
  //   emptyEnterResets?: boolean;
  //   emptyChildEnter?: "outdent" | "exit-at-end" | "stay";
  //   childrenCanOutdent?: boolean;
  // }
  meta?: {
    selectable?: boolean;
    fileBlockAccept?: string[];
    code?: boolean;
    defining?: boolean;
    isolating?: boolean;
    draggable?: boolean;
    highlight?: (block: Block) => string | undefined;
  };
};
```

`render:` 这是您的 React 组件，定义了自定义区块在编辑器中的渲染方式，接收三个 React props：

- `block:` 要渲染的区块。其类型和属性将与区块配置中定义的类型和 PropSchema 匹配。

- `editor:` 区块所在的 BlockNote 编辑器实例。

- `contentRef:` 可用于标记区块中哪个元素可编辑的 React `ref`。仅当区块配置包含 `content: "inline"` 或 `content: "plain"` 时可用。

`renderFrame?:` 用于围绕区块内容及其子区块绘制框架的组件。请参阅[区块框架](#block-frames)。

`toExternalHTML?:` 该组件在区块导出为 HTML、供 BlockNote 之外使用时调用，例如复制到剪贴板时。如果未定义，BlockNote 会使用 `render`（如果该区块定义了 `renderFrame`，也会使用它）转换 HTML。它接收与 `render` 相同的 props，以及另外两个属性：

- `childrenRef:` React `ref`，用于标记区块子内容应放置的位置，例如 `<details>` 元素内部。若未指定，子区块会跟在当前区块之后。

- `context:` 对象，包含以下属性：
  - `nestingLevel:` 当前导出区块嵌套在其他区块中的深度。`0` 表示位于文档顶层。

<Callout type="info">
  _请注意，传入 `toExternalHTML` 的组件会在一个独立的 React 根实例中渲染和序列化，因此无法使用依赖于 React 上下文的 Hooks。_
</Callout>

`parse?:` `parse` 函数定义了如何将 HTML 内容解析为您的区块，例如从剪贴板粘贴内容时调用。如果元素应解析为您的自定义区块，则返回该区块应有的 props；否则返回 `undefined`。接收一个参数：

- `element`: 正在解析的 HTML 元素。

`parseContent?:` 与 `parse` 一起使用的高级选项，可让您在将 HTML 转换为区块时进行更多控制。当 `parse` 返回非 `undefined` 值时运行，其作用对应于 ProseMirror API 中的 [getContent](https://prosemirror.net/docs/ref/#model.TagParseRule.getContent)。

`runsBefore?:` 如果该区块具有需要优先于其他区块进行解析的内容或扩展，可以在此处传入其 `type` 数组。

`experimental_keyboard?:` 指定键盘如何处理该区块及其子区块。此 API 目前处于实验阶段，未来可能变化。只需填写与默认行为不同的设置。若需根据区块属性决定设置，可传入一个接收区块并返回设置的函数。

- `enter?:` 在区块内容中按 Enter 时的行为。默认的 `"split"` 会拆分区块，将光标后的文本移到下方的新区块。`"into-children"` 会将其移入第一个子区块。`"line-break"` 会插入换行，并使 Shift-Enter 执行相同操作。对于无法包含硬换行节点的 `content: "plain"` 区块，换行会插入字面换行符（`"\n"`）。

- `shiftEnter?:` 在区块内容中按 Shift-Enter 时的行为：默认的 `"line-break"`，或 `"same-as-enter"`。

- `splitKeepsType?:` 按 Enter 拆分区块时，新建区块是否沿用当前区块类型（例如列表项）。默认为 `false`。

- `splitKeepsChildren?:` 按 Enter 拆分区块时，子区块是否留在当前区块。否则它们会随光标后的文本移到新区块，如同嵌套区块的行为，新区块会移到子区块上方并占据原位置。`enter` 为 `"into-children"` 时默认为 `true`（子区块构成该区块的主体）；关闭状态的 toggle 也会设置为保留其隐藏子区块。

- `resetsTo?:` 重置区块时要转换成的类型，同时保留内容和子区块。在区块开头按 Backspace 总会重置区块。此设置包含 `type`，以及要合并到区块属性中的 `props`。默认为 `{ type: "paragraph" }`。

- `emptyEnterResets?:` 在空区块中按 Enter 时是否也重置区块，例如空列表项变为段落。默认为 `false`。

- `emptyChildEnter?:` 在该区块的空子区块中按 Enter 时的行为。默认的 `"outdent"` 会提升任何空子区块的层级。布局块默认使用 `"exit-at-end"`：最后一个空子区块会移到布局块之后，其他空子区块后则会新增一个子区块。`"stay"` 总是在空子区块后新增子区块。

- `childrenCanOutdent?:` 子区块是否可以通过 Shift-Tab，或在空子区块、嵌套子区块中按 Enter 或 Backspace 来移出该区块。默认为 `true`；布局块中默认为 `false`，其子区块不能移出。

多个设置同时适用时，在非空内容开头按 Enter 总会在其上方插入空区块；重置空区块的行为优先于 `enter: "into-children"`。

`meta?:` 用于设置区块的各种通用属性的对象。

- `selectable?:` 可以设置为 false，使区块不可被鼠标和键盘选中。这也有助于能选中区块中不可编辑的内容。仅当 `content` 为 `none` 时才应设置为 false，默认为 true。

- `fileBlockAccept?:` 对于自定义文件块，可指定接受的 MIME 类型（例如 `"application/pdf"` 或 `"image/*"`）或文件扩展名（例如 `".pdf"`）。它控制文件上传选择器，以及拖放或粘贴文件时使用的区块类型。请参阅[自定义文件块](#custom-file-blocks)。

- `code?:` 该区块是否包含 [代码](https://prosemirror.net/docs/ref/#model.NodeSpec.code)。

- `defining?:` 该区块是否为 [defining](https://prosemirror.net/docs/ref/#model.NodeSpec.defining)。

- `isolating?:` 该区块是否为 [isolating](https://prosemirror.net/docs/ref/#model.NodeSpec.isolating)。

- `draggable?:` 该区块是否显示侧边菜单拖动手柄。默认为 `true`；对于只能放入指定父级的布局块（`placeable: "namedOnly"`），默认为 `false`。

- `highlight?:` 返回区块文本应进行语法高亮的语言的回调（如果不进行高亮则返回 `undefined`）。只有在编辑器中添加了[语法高亮扩展](/docs/features/blocks/code-blocks#syntax-highlighting)时，高亮才会生效。

### 区块扩展

尽管本页示例未使用，`createReactBlockSpec` 接受第三个可选参数 `extensions`。用于添加特定于该区块的编辑器 `extensions`，您可以在 [此处](/docs/features/extensions) 了解更多。

区块扩展通常用于添加键盘快捷键，以便将当前区块类型切换为自定义区块。例如，一个目录区块的扩展可能会添加一个 ProseMirror 插件，用以扫描标题并生成目录。

### 区块配置选项

在某些情况下，您可能希望区块配置可自定义。例如，您可能希望代码区块支持不同的语法高亮（如 web 或嵌入式代码），或标题区块支持灵活的标题级别数。您可以对该用例使用相同的 API，做一些小改动：

```typescript
// 区块可接受的任意选项，例如标题级别数或可用的代码高亮语言。
type CustomBlockConfigOptions = {
  ...
}

const createCustomBlock = createReactBlockSpec(
  createBlockConfig((options: CustomBlockConfigOptions) => ({
    type: "customBlock"
    propSchema: ...,
    content: ...,
  })),
  (options: CustomBlockConfigOptions) => ({
    render: ...,
    ...
  })
)

const options: CustomBlockConfigOptions = {
  ...
};

const schema = BlockNoteSchema.create().extend({
  blockSpecs: {
    // 创建定制区块的实例，并添加进 schema。
    customBlock: createCustomBlock(options),
  },
});
```

你可以看到，我们不再为配置和实现传入普通对象，而是传入函数。这些函数接收区块选项作为参数，并分别返回配置和实现对象。另外，用于创建配置的函数被 `createBlockConfig` 包裹。

另外请注意，本页示例中，我们通过调用 `createAlert()`（无参数）创建了新的 Alert 区块实例。而对自定义区块若有选项，则可按上述方式传入。

要查看使用区块选项的完整示例，请参考 [内置标题区块](https://github.com/TypeCellOS/BlockNote/blob/main/packages/core/src/blocks/Heading/block.ts)。

## 将自定义区块添加到编辑器

最后，使用您定义的自定义区块创建一个 BlockNoteSchema：

```typescript
const schema = BlockNoteSchema.create({
  blockSpecs: {
    // 如需启用默认区块，请使用展开语法
    ...defaultBlockSpecs,

    // 添加您自己的自定义区块：
    alert: createAlert(),
  },
});
```

然后您可以按照[自定义 Schema](/docs/features/custom-schemas)页面中说明的，使用此自定义 Schema 实例化您的编辑器。

## 自定义文件块

要扩展内置文件块的行为，添加新的文件类型或预览，请使用 `createReactBlockSpec`，并沿用内置块的文件属性和渲染包装器：

1. 将 `content` 设为 `"none"`，并包含 `name`、`url` 和 `caption` 属性，每个属性的 `default` 都设为 `""`。你可以复用 `@blocknote/core` 导出的 `createFileBlockConfig().propSchema`。
2. 在块实现中设置 `meta.fileBlockAccept`，例如 PDF 文件使用 `["application/pdf"]`。
3. 从 `@blocknote/react` 导入并渲染 `FileBlockWrapper`，将渲染属性传给它，并把预览作为子元素。它会提供添加文件按钮、上传加载状态和说明文字；没有预览时，则显示文件名和图标。若希望文件名也显示在预览旁边，请在预览子元素中包含文件名。若需可调整大小的预览，请改用 `ResizableFileBlockWrapper`，并添加数值型 `previewWidth` 属性。添加默认值为 `true` 的布尔型 `showPreview` 属性，让用户可以在预览和文件名与图标之间切换。
4. 将块 spec 添加到你的[schema](/docs/features/custom-schemas#creating-your-own-schema)中，并放在其他接受相同文件的文件块之后：拖放或粘贴文件时，schema 中最后一个匹配的块 spec 会生效。配置 [`uploadFile`](/docs/react/components/image-toolbar#file-upload) 以启用上传。保留 `defaultBlockSpecs.file` 作为未匹配文件的回退类型。若要让用户插入空白区块，请添加[斜杠菜单项](/docs/react/components/suggestion-menus#changing-slash-menu-items)。

目前包装器的 TypeScript 类型针对内置的 `"file"` 区块，因此自定义区块的渲染属性不能直接赋给它。下面的 PDF 示例在包装器边界使用类型断言来处理这一限制。

## 区块框架

区块可以包含子区块。默认情况下，BlockNote 会在区块下方缩进显示子区块。使用 `renderFrame` 可为区块内容及其子区块绘制统一框架，例如让两者共享同一背景。

在下面的演示中，我们为上方演示中的 Alert 区块添加标题和正文。警告文本作为标题，子区块作为正文；框架会根据警告类型设置标题和正文的背景色：

<Example name="custom-schema/alert-block-with-title-and-body" />

块配置本身无需更改。包含内容（`content: "inline"` 或 `"plain"`）的区块始终可以包含子区块，因此无需声明。我们在块实现中添加 `renderFrame` 和 `experimental_keyboard`：

```tsx
export const createAlert = createReactBlockSpec(
  {
    type: "alert",
    propSchema: {
      type: {
        default: "warning",
        values: ["warning", "error", "info", "success"],
      },
    },
    content: "inline",
  },
  {
    experimental_keyboard: {
      enter: "into-children",
      childrenCanOutdent: false,
      emptyChildEnter: "exit-at-end",
    },
    // Draws the title row, the same as in the Alert demo.
    render: (props) => {
      ...
    },
    renderFrame: (props) => (
      <div className="alert-frame" data-alert-type={props.block.props.type}>
        <div ref={props.slotRef} />
      </div>
    ),
  },
);
```

`render:` 只绘制区块内容，此处是 Alert 的标题行。添加框架不会改变它。

`renderFrame:` 绘制框架的 React 组件，接收三个 React props：

- `block:` 当前区块。可使用它的属性调整框架，例如显示对应警告类型的颜色。
- `editor:` 当前区块所在的 BlockNote 编辑器实例。
- `slotRef:` React `ref`，应挂到容纳区块内容及其子区块的元素上。可在该元素周围添加图标或按钮等其他元素；请为这些元素设置 `contentEditable={false}`。

若要让区块不显示框架，请返回 `null`。例如，可以通过区块属性控制是否显示框架。

`experimental_keyboard:` 如果不设置这些选项，子区块的行为与其他嵌套区块相同。此处的设置会让正文留在 Alert 中：

- `enter: "into-children"`：在标题中按 Enter，会在正文开头添加区块。
- `childrenCanOutdent: false`：按 Shift-Tab 不会将区块移出 Alert。
- `emptyChildEnter: "exit-at-end"`：在正文最后一个空区块中按 Enter，会将该区块移出 Alert。

上述[区块实现](#block-implementation-reactcustomblockimplementation)部分列出了 `experimental_keyboard` 的所有设置。

使用 `content` 设置标题，使用 `children` 设置正文：

```typescript
{
  type: "alert",
  content: "Before you start",
  children: [
    { type: "paragraph", content: "Make sure you have an account." },
  ],
}
```

用户移动 Alert 时，标题和正文会一起移动。

<Callout type="info">
  _带框架的区块不同于[布局块](/docs/features/custom-schemas/layout-blocks)。布局块自身没有内容，只容纳子区块，例如面板或标签页组。请参阅[布局块与区块框架](/docs/features/custom-schemas/layout-blocks#layout-blocks-and-block-frames)。_
</Callout>
